## 編集と公開

重松さん・宮後さん・水金さんの各担当者は、作業前に最新mainと上記文書、開いているPRを確認します。依頼ごとに固有の `codex/` ブランチとPRを使い、担当・対象範囲・関連PRを明記します。同じ作業ブランチの使い回し、mainへの直接push、force pushは行いません。

検証はリポジトリのルートで実行します。

```sh
node scripts/check.mjs
```

Node.js 20以降で、JavaScriptとHTML内スクリプトの構文、本アプリが参照するファイル、共通文書と既存テストを確認します。外部APIへ通信せず、本番データを読み書きしません。ブラウザ用の `retry-test.js` などをNodeのテストとして誤実行しないよう、テストは `tests/*.test.cjs` を明示して実行します。

公開の順序は、**専用ブランチ → 検証 → PRのCI成功 → 最新mainとの再照合 → SHA指定でマージ → 既存Pagesの公開成功 → `/app/` の実画面確認**です。mainのルートを公開する既存のPages設定を維持するため、マージ前の検証確認が必須です。ブランチ保護や編集ロックを新設したことを意味しません。

## 本アプリと接続先

`app/` が本アプリです。現在の接続設定は `app/configuration.js`、画面のAPI連携は `app/operations.js`、見た目は `app/workspace.css`・`app/workspace.js` などで管理します。変更対象は毎回最新の参照関係から確認してください。

データ保存・認証・金額閲覧制限などのGAS処理は [GAS側のリポジトリ](https://github.com/sunpre-ai/eigyo-no-aibo) も関わります。必要な場合は両方の最新mainと更新ルールを確認し、関連PR・反映順・互換性を明記します。Topにある画面を、旧コードから無条件に生成し直して上書きしません。

本アプリのURL、manifestのid・scope・start_url、既存の権限と業務データを維持します。PWAの静的ファイル更新では、該当サービスワーカーのキャッシュ版と利用者の更新方法も確認します。API応答・認証情報・業務データを静的キャッシュへ追加しません。

## 試験画面

ルートの通信試験、`mockup/`、`integration-trial/` などは本アプリと別です。試験画面へ実在の顧客・案件・個人情報・金額を入力しないでください。以前の試験用説明は [試験画面について](docs/試験画面について.md) に残しています。

## 公開後

担当AIは対象コミットのCIとPages公開結果を確認し、別タブの本アプリで変更箇所を確認します。入力途中の利用者画面は閉じたり再読み込みしたりしません。コード保存・Pages公開・GAS反映・実画面確認を区別して報告します。
