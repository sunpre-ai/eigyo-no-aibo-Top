# 3人で営業の相棒を更新する

## 共通の入口

本アプリの画面は [Topのリポジトリ](https://github.com/sunpre-ai/eigyo-no-aibo-Top) で編集します。[本アプリ](https://sunpre-ai.github.io/eigyo-no-aibo-Top/app/) と、ルートの通信試験・`/mockup/` の画面見本を区別してください。

各人が自分のGitHub接続で作業します。リポジトリへの参加、ChatGPTのGitHub接続、Google側のシートやGASの権限は別です。共同編集のために他人のGoogle認証ファイルやトークンを受け取る必要はありません。

## 作業を重ねない手順

1. 最新mainと [AGENTS.md](../AGENTS.md)、[運用ルール](運用ルール(AI用).md) を読みます。
2. 開いているPRで、担当・対象ファイル・画面・関数を確認します。同じ画面の同じ処理が対象なら、変更箇所を分けるか先行PRの統合を待って取り込みます。別の関数・文書なら並行作業できます。
3. 依頼ごとに自分専用の `codex/` ブランチと作業領域を作ります。ブランチ名には内容・日付・識別子を入れます。長い作業はDraft PRで早めに担当・対象範囲を見えるようにします。
4. 対象範囲が変わったらPR説明も更新します。他人のPRは勝手にマージ・終了しません。
5. マージ直前にmainを取り込み直し、他の人の変更が残っていることと検証結果を確認します。仕様が衝突する場合だけ、必要な判断を本人へ戻します。

担当表を別シートに作る方式にはしません。各PRを作業状況の共有場所にするため、別チャットの作業内容を自動的に知っているとは扱わないでください。同時編集の完全な防止を保証する仕組みではありません。

## 普段の依頼文

```text
営業の相棒を修正してください。
対象は https://github.com/sunpre-ai/eigyo-no-aibo-Top です。
最新mainのAGENTS.md、docs/共同編集.md、docs/運用ルール(AI用).mdと
開いているPRを確認し、他の担当者の作業範囲と重ならない専用ブランチで進めてください。

修正内容：
（ここに希望を書く）

node scripts/check.mjsで検証し、最新mainとの整合と最新コミットのcheck成功を確認してから、
通常修正はそのSHAを指定してPRをマージしてください。
Pagesの公開成功と本アプリ/app/の代表的な操作まで確認してください。
GASも変更する場合は、両リポジトリの正本・PR・反映順を確認してください。
権限・保存先・データ移行などは、具体的な影響と手順を示して確認してください。
```

「提案だけ」「PRまで」と依頼すれば、その範囲で止めます。通常の修正では、毎回本人にGit操作やコードの貼り付けを依頼しません。

## 更新完了の見分け方

- 最新mainを含むPRの最新コミットで `check` が成功し、確認したSHAを指定して統合している。
- 対象コミットのPages公開が成功している。
- `/app/` で変更箇所を確認し、PWAの更新も必要に応じて確認している。
- GASの変更がある場合はGAS側の反映も区別して報告している。

ログインなどで実画面を確認できない場合は、確認済みの範囲と残った操作を説明します。公開しただけで操作確認まで完了したとは報告しません。
